## 写作约定

1. **区分事实与推断**：公开信息能证实的直接写；推断的写「推断：…」；找不到或口径冲突的写「⚠️ 待核实」，并写清核实路径（问谁 / 看哪份 DD / 上哪个页面）
2. **不编合约地址、不编 APY**：数字必须带来源和时间戳，因为 TVL/APY 天天变
3. **数据接入章节是重点**：这份文档的第一读者是中台解析同学，不是市场同学
4. **中文正文，专有名词保留英文**（vault / NAV / epoch / Locked / Flexible 等）

## 2. 协议背景

## 3. 底层资产（Underlying）→ 对应详情页 Underlying Tab

底层到底是什么资产、谁管、存在哪、怎么估值。

## 4. 收益来源（Yield Source）→ 对应详情页 Yield Source Tab

收益从哪来（几条腿分别写），是否含代币激励 / 积分。

## 5. 链上机制与凭证代币

- 凭证代币符号 / 标准（ERC-20 / ERC-4626 / SPL）
- 合约地址（⚠️ 未验证的标注出来）
- NAV / 汇率怎么表达（`convertToAssets`？ 官方 oracle？ 链下 NAV 推送？）
- 申购路径、赎回路径（是否队列 / epoch / 通知期）
- 是否可组合（Pendle / Morpho / Kamino 等）
