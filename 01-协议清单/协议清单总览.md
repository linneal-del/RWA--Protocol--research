**这批实测里对解析最有价值的七条**（按严重程度排）：

1. 🔴🔴 **「份额代币 `Transfer(from=0x0)` = 申购」这条通用规则是错的。** Morpho Katana 实测：一笔存款里该事件出现 **2 次** —— 一次给用户，一次是给 curator 多签的 **performance fee**。必须改用 `Deposit` 事件的受益人字段，且**字段名两条链还不一样**（Base `onBehalf` / Katana `owner`）。见 [Morpho.md](../02-协议调研/Morpho.md) §5.5
2. 🔴🔴 **「赎回中」的资产可能完全读不到。** Renzo ezSOL 赎回时份额被转进一个**新建的 ticket PDA**，用户侧任何代币余额都看不到这笔待领取资产 —— 用户会觉得钱凭空少了。见 [Renzo.md](../02-协议调研/Renzo.md) §5.4
3. 🔴 **「同底层 = 同机制」的假设不成立。** Fragmetric 和 Renzo ezSOL 都跑在 **Jito Restaking** 上，赎回却完全相反：一个 `Burn` + 铸凭证，一个不销毁、转入托管 PDA。**每个协议必须单独实测**
4. 🔴 **Morpho 固定利率产品完全没有凭证代币** —— 持仓只存在 `Midnight` 合约的 `(marketId, user)` 记录里，且收益是**折价买入到期兑付**，不体现在余额增长上，PNL 按余额差算等于 0
5. 🔴 **Haedal 三条赎回路径的链上事件完全不同，但 haSUI 余额变化一模一样**（`UserNormalUnstaked` 不到账 vs `UserInstantUnstaked`+DEX `SwapEvent` 即时到账）→ 只看 balance change 必判错
6. 🔴 **一笔交易里可能有两套 shares。** Morpho 金库存款连锁触发三层，`VaultV2.Deposit.shares` 是用户的、`Morpho.Supply.shares` 是金库的，拿错就把金库仓位算成用户的
7. 🔴 **精度与估值链路每条线都不同**：Renzo ezUSDC1 份额价 ≈4.376 且 decimals=6（按 1:1 或 18 位都错）；Morpho Base 存在 6/18 错配；Morpho Katana 多一层 vbETH 包装、要三次换算；Renzo ezSOL 赎回得到的是 **JitoSOL**（本身又是 LST）

📌 **一个横跨多协议的共性坑**：**交易发起人 ≠ 受益人**。Ember 批处理的 `tx.from` 是项目方 operator、Morpho 的 `sender` 是适配器、Orca 和 Renzo ezSOL 的 feePayer 是 relayer。**任何按 `tx.from` / `sender` 归集用户交易的实现都会漏单或错配。**
