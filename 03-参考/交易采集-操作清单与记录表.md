> **这是本轮调研的核心交付物。** 目标只有一个：**把用户在页面上能做的每一种操作，都亲手做一遍，留下「操作步骤 + 交易类型 + hash + 截图」四件套。**
> 建立时间：2026-08-03

## 一、为什么必须自己操作（结论修正）

我之前建议"从区块浏览器捞别人的交易就行，免费又快"。**这条建议在本用途下是错的**，Scott 的理由是决定性的：

> 「你在页面的操作是模拟用户能几乎操作的全部。但是如果给你 hash，其实你不太能确认**哪个 hash 是操作哪一步产生的**。」

**两种做法的区别**：

| | 捞别人的 hash | 自己操作 |
|---|---|---|
| 能拿到样本交易 | ✅ | ✅ |
| **能确定这条 hash 对应哪一步操作** | ❌ **不能** | ✅ 能 |
| 能保证覆盖了**所有**交易类型 | ❌ 不能（只能捞到别人恰好做过的） | ✅ 能（按清单逐项走） |
| 能留下操作过程的截图 | ❌ 不能 | ✅ 能 |
| 能发现页面文案与链上行为不一致 | ❌ 不能 | ✅ 能 |

→ **捞 hash 只适合"验证解析结果对不对"，不适合"定义要解析哪些东西"。** 后者是我们现在要做的事。

**另一个现实约束**：测试币申请**没有额度**（Scott 2026-08-03 确认）→ 只能用**主网小额真金白银**操作。

## 二、四件套：每一笔都要有

| 项 | 内容 | 为什么要 |
|----|------|---------|
| **① 操作步骤** | 我在页面上点了什么（含第几步） | 让解析同学知道这笔对应哪个用户动作 |
| **② 交易类型** | Approve / 申购 / 赎回申请 / 赎回到账 / … | 这是解析器要输出的分类，必须由我们定义 |
| **③ tx hash** | 交易哈希（Solana 是 signature） | 解析同学的输入 |
| **④ 截图** | 操作确认页 + 成功页 | 证明页面显示的数字与链上一致；也是给 PM/QA 的验收依据 |

## 三、交易类型穷举清单（Scott 问的"全不全"就是这个）

### 3.1 通用类型（每个协议都要过一遍）

| # | 交易类型 | 说明 | 容易被漏 |
|---|---------|------|:---:|
| 1 | **Approve（授权）** | 首次申购前授权代币 | 🔴 **最常被漏**：它是**独立的一笔交易**，不是申购的一部分 |
| 2 | **申购 / Stake / Mint** | 存入本金拿凭证 | |
| 3 | **追加申购** | 已有持仓后再买 | 🔴 容易漏。要验证成本基准是否正确累加 |
| 4 | **部分赎回** | 只赎回一部分 | 🔴 容易漏。验证剩余持仓算得对不对 |
| 5 | **全部赎回** | 清仓 | |
| 6 | **赎回申请**（两段式协议） | 提交申请，钱还没到 | 对应 PRD 的「赎回中」状态 |
| 7 | **赎回到账**（两段式协议） | 钱真正到账 | |
| 8 | **失败交易** | 金额低于最低申购额、授权不足等 | 🔴 能暴露合约限制条件 |

### 3.2 各协议特有类型（按我实测发现的机制补的）

| 协议 | 特有操作 | 为什么必须单独测 |
|------|---------|----------------|
| **Ember**（Bitwise Premium+） | 🔴 **申购后等「每日批处理」** | 页面写 Daily Processing / Shares Received: After processing。**存入和铸份额可能是两笔**，这段真空期用户持仓会显示 0 → 直接决定 PRD 要不要加「申购中」状态 |
| **Ember** | **赎回（最长 7 天）** | 大概率也是两段式 |
| **Nest**（nOPAL） | 🔴 **Instant 赎回（0.15% 费）** | 与下一行是**两种不同的赎回**，费率差 10 倍 |
| **Nest** | 🔴 **Standard 赎回（0.015% 费）** | 后台只有一个「赎回费」字段，装不下两种 → 需要证据去找 Marcus |
| **Nest** | **Bridge（跨链）** | 页面有 Bridge tab。nOPAL 三链同一地址，跨链后持仓怎么算要测 |
| **Re** | 🔴 **reUSD 和 reUSDe 各走一遍** | 两个独立投资品，入口合约不同、申购币种不同（USDC vs USDe） |
| **Re** | **Swap tab** | 页面除 Mint/Redeem 外还有 Swap，是二级市场换币，**不应算作申购** |
| **Unitas**（XGLD） | **Swap（XAUT → XGLD）** | 申购币种是 XAUT 不是稳定币，要先换到 XAUT |
| **Unitas** | **PancakeSwap 二级买入** | 页面自己推荐这条路。**成本基准来源和 mint 完全不同**，必须有样本 |
| **Unitas** | **Bridge / Rewards 页操作** | 有 Booster Earn 活动 → 对应 PRD 的 Campaign Bonus |
| **DMZ**（rAI） | 🔴 **每周派息到账** | **唯一必须等待的**（被动收款，不是主动操作）。是 PNL 公式的关键 |
| **Ondo**（USDY） | **申购 / 赎回** | 顺便确认拿到的是 USDY 还是 rUSDY（决定要不要做 NAV 曲线） |
| **OpenTrade** | ⚠️ **先确认域名** | `primeplusvault.lovable.app` 不是 opentrade.io 主域，**确认前不要连钱包** |

### 3.3 顺序建议

```
第 1 天：DMZ 先申购（因为要等一周才有派息）
         → 然后 Nest、Unitas、Ondo（都在 BNB 链，gas 便宜）
第 2 天：Ember、Re（Ethereum，gas 较贵，集中一次做完省手续费）
第 8 天：回来收 DMZ 的派息 hash
过程中：赎回类操作放在申购后隔一天做（有些协议有冷却期）
```

## 五、截图怎么截才有用

**每笔操作至少两张**：

| 时机 | 要截到什么 | 作用 |
|------|-----------|------|
| **① 确认页**（点最终按钮前） | 金额、币种、预计收到、费用、锁定期、按钮文案 | 证明**页面承诺了什么** —— 后面链上数据对不上时这就是证据 |
| **② 成功页** | 成功提示、交易 hash 或"查看交易"链接 | 建立 **hash ↔ 这一步操作**的铁证（Scott 担心的就是这个） |

**加分项**（有就截）：
- 操作前后的**持仓页面**（验证持仓解析对不对）
- **钱包弹窗**（能看到实际调用的合约地址和方法）
- 页面上的**合约地址栏**（顺手把地址也拿到）

**命名规则**（别用「截屏2026-08-03 15.51.18.png」，事后完全对不上）：
```
<协议>-<序号>-<类型>.png

例：Nest-01-approve.png
    Nest-02-mint.png
    Ember-03-deposit-pending.png
    DMZ-05-dividend.png
```

## 六、怎么保证「hash ↔ 操作」不会错位（Scott 的核心担心）

这是本文档最关键的一节。三个动作就够了：

**1. 一次只做一笔，做完立刻记录**
不要连着点五个操作再回头补表 —— 那就退回到"分不清哪个 hash 是哪一步"了。

**2. 从"成功页"直接拿 hash，不要事后去浏览器翻**
多数协议成功页会给「View transaction」链接，点开就是那笔。**这是最强的对应关系证据。**
如果页面不给，就打开钱包的**交易历史**（按时间倒序，最上面那笔就是刚才的）。

**3. 用「时间戳」做双重校验**
表里记下操作时间，交易在链上也有时间戳。**两者对不上就说明记错了行。**

> 💡 **一个笨但极其有效的办法**：操作前后各截一张，截图里带着系统时间（macOS 截图自带时间在文件名里）。事后核对时，用"截图时间 → 链上时间"就能锁定是哪一笔，不会串行。

## 七、成本预估

测试币没有额度，只能用主网。但**验证解析只需要最小额**：

| 链 | 涉及协议 | gas 成本 |
|----|---------|---------|
| **BNB Chain** | Nest、Unitas、Ondo、DMZ | 很便宜，一笔几毛到几块 |
| **Ethereum** | Ember、Re | **较贵**，一笔几美元到几十美元 → 建议同一天集中做完 |

**要留意的三笔额外成本**：
1. **Unitas 需要先换到 XAUT**（申购币种不是稳定币），多一步兑换成本
2. **Re 要做两遍**（reUSD 用 USDC、reUSDe 用 USDe），且都在 Ethereum
3. **部分产品有最低申购额**（PRD 里举的例子是 1,000 USDC 起投）—— 页面上会写，**先看清再决定投多少**

⚠️ **风险提醒**：这些是真实理财产品，有本金风险；**reUSDe 官方文档写的是季度赎回**（虽然页面没显示周期），买了可能短期取不出来 → **reUSDe 只投最小额**。

## 八、我已经捞到的 hash 怎么用

之前捞的 6 条（Re×3、nOPAL×1、XGLD×2）**不作废，但换个用途**：

| 用途 | 说明 |
|------|------|
| ❌ 不用于 | 定义交易类型清单（因为不确定对应哪一步操作） |

| ✅ 用于 | **合约地址与 decimals 已确认**（见 [已确认合约地址与链上实测.md](已确认合约地址与链上实测.md)），你操作时可以直接核对钱包弹窗里的地址对不对 |
