## 二、最值得注意的四组交叉

### 1. 🔴 Ember 是其他三个协议的"套娃层"

[Ember.md](../02-协议调研/Ember.md) 的循环贷标的是 **PST（Huma）+ sUSDai（USD.AI）+ PRIME（待确认是否为 OpenTrade PRIME+）**。

如果我们**同时上线 Ember、Huma、USD.AI、OpenTrade**：
- 用户看到 4 个独立产品
- 实际上 Ember = 另外三个的**杠杆包装**
- **底层信用事件会同时打击 4 个产品，且 Ember 因为有杠杆会亏得更多**

→ **建议**：Ember 的 Risk Tab 必须明确写"本产品的底层是本平台其他 RWA 产品的杠杆组合"。

### 2. 🔴 Re + OnRe = 同一类风险（再保险）+ 同一底层（sUSDe）

两个都是链上再保险、两个都吃 Ethena 收益、两个都是**季度赎回**。
- 巨灾年份（如大飓风季）**两者会同时回撤**
- 若 Ethena 出问题，**两者同时受影响**

→ **建议**：产品层面考虑是否只上一个；若都上，风险标签要能让用户看出同质性。

### 3. Unitas XGLD vs XAUE = 直接竞品

见 [XAUE.md](../02-协议调研/XAUE.md) 的对比表。都是"XAU₮ + DeFi 收益"，收益率都是 1.5–3%。差异主要在杠杆（XGLD 有 70% LTV，XAUE 无）和准入（XAUE 需白名单）。

→ **建议**：选一个。**XGLD 已接入且无白名单限制，优先级更高**。

### 4. Ondo QYLDon vs DMZ rAI = 同一策略（纳指 covered call）

两者底层策略高度重叠（都是卖纳指备兑看涨期权）。差别：
- QYLDon = 代币化 QYLD ETF，分红**自动再投资**（NAV 型）
- rAI = 自建策略，**每周派 USDT**（现金流型）

→ **建议**：如果都上，前端要能让用户理解"一个滚存、一个派息"的区别，否则会被当成重复产品。

## 四、赎回流动性分档（决定一期该上哪些）

| 档位 | 协议 | 赎回条件 |
|------|------|---------|
| 🟢 **即时 / 同日** | OpenTrade（同日约 6h）、Ondo USDY、Nest（无赎回费）、Midas（即时层约 10% TVL） | 适合活期展示 |
| 🟡 **T+N / 队列数天–两周** | Ember（需解杠杆）、Unitas、Theo（约两周）、Ethena sUSDe（若有 7 天 cooldown） | 需 request ID |
| 🔴 **月度 epoch / 季度窗口** | **USD.AI（30 天 epoch + FIFO，可跨月）**、**Re reUSDe（季度）**、**OnRe（季度 + 30 天通知期）** | **标"活期"会误导用户** |
| ⚫️ **不明 / 可能有锁定期** | DigiFT pEAK、Asseto NGI+ | 需先问清再评估 |

📌 **给一期的建议**：优先 🟢 档 + 🟡 档；🔴 档若要上，**必须先解决 PRD 的"赎回中"状态与赎回窗口展示**（见 [../00-背景/02-PRD要点-数据侧视角.md](../00-背景/02-PRD要点-数据侧视角.md) 第五节）。

## 六、给 Linnea 的三个行动建议

1. **先和 Marcus 对齐"池子类别"口径**：CSV 里 **6 个协议标「活期」但实际是队列/季度赎回**（USD.AI、Re reUSDe、OnRe、Theo、Asseto、DigiFT）。这是全表最系统性的错误，且直接影响 PRD 的时间线组件与赎回流程。

3. **把 DMZ 的 PNL 口径单独拉一次对齐**：它是唯一的派息型产品，`PNL = NAV 变化 + 累计派息`，若沿用通用公式会**严重低估收益**，是最容易上线后才发现的 bug。
