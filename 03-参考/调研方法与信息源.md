# 调研方法与信息源

> 记录这批调研是怎么做的、哪些信息可信、哪些踩了坑。下一轮补充调研时先看这页。
> 整理时间：2026-07-31

## 一、调研流程

```
1. 读模版        → 8月待冲刺RWA协议列表.md（表头字段）
2. 读全量字段    → [Master] RWA Season - 产品信息.csv（20 行 / 19 列）
3. 读需求侧      → PRD v81 + 需求对齐会 + Scott 待办（明确"调研要产出什么"）
4. 逐协议检索    → 官方 docs 优先 → 官方博客/新闻稿 → 一线媒体 → 数据站 → 第三方研究
5. 交叉验证      → 链、代币机制、赎回条款三项必须至少两个来源一致
6. 落盘          → 统一模版，冲突项标 ⚠️，缺口写清"问谁"
7. 归并          → 组合层风险与交叉依赖.md（跨协议的相关性）
```

## 二、信息源可信度分级（本次实测）

| 级别 | 来源 | 实测评价 |
|------|------|---------|
| ⭐⭐⭐ | **官方 docs 站**（docs.re.xyz、docs.usd.ai、docs.onre.finance、docs.opentrade.io、docs.nest.credit、learn.ember.so、docs.ondo.finance、docs.chain.link） | 机制描述最准确，**赎回条款只能从这里拿**。本次最有价值的发现全部来自 docs |
| ⭐⭐⭐ | **Chainlink 文档** | Ondo GM 的 sValue 机制说明比 Ondo 自己的文档更清楚，**做解析必读** |
| ⭐⭐ | 官方博客 / 新闻稿（plume.org/blog、prnewswire、falconx.io/newsroom） | 上线时间、合作方、规模可信；APY/TVL 是快照 |
| ⭐⭐ | 一线媒体（The Block、CoinDesk、Decrypt、Cryptobriefing） | 事实可信，数字有时滞 |
| ⭐⭐ | 独立研究（stablewatch.io、OAK Research、Messari、Steakhouse、alearesearch） | **风险分析质量最高**，本次 USD.AI 的 epoch 队列风险、Theo 的 Mustafa 集中风险都来自这里 |
| ⭐ | 数据站（RWA.xyz、DefiLlama、CoinGecko、vaults.fyi） | 用于交叉验证 TVL/APY；**vaults.fyi 能查到具体金库地址与 curator**，本次靠它定位了 Ember 的合约 |
| ⚠️ | 交易所资讯（KuCoin、MEXC、Bitget、Gate academy） | 可作补充，**但时间线常出错**（XAUE 的上线时间就在这类来源里冲突） |
| ❌ | 内容农场 / AI 洗稿站（ainvest、部分聚合站） | 数字互相矛盾，不采信 |

## 三、踩过的坑（下次直接避开）

1. **同名项目撞车**
   - **Ember**：ember.so（本次目标）／Sui 上的 Ember Protocol（Bluefin 孵化）／Core 上的比特币抵押借贷 Ember ——**三个不同项目**
   - **Asseto vs Real Finance**：CSV 的产品页域名是 `reale.finance`，但 NGI+ 的平台是 `asseto.finance`；另有一个无关的 `real.finance`
   - → **对策**：搜到结果先核对"链 + 代币符号"两项，不一致就是撞车

2. **403 / 反爬**
   - `ember.so`、`reale.finance` 都返回 403（Cloudflare 类防护），WebFetch 拿不到
   - → **对策**：改查 `docs.*` / `learn.*` 子域；或用数据站（vaults.fyi、rwa.xyz）反查；实在不行让人用浏览器打开

3. **CSV 的链字段不可全信**
   本次至少 4 处冲突：Nest nOPAL（CSV 写 BNB，官方是 Plume/Solana/ETH/AVAX）、Midas mF-ONE（CSV 写 BNB，官方是 Ethereum）、XAUE（CSV 写 BNB，官方是 Ethereum）、Ondo USDY（CSV 写 BNB，公开资料未见 BNB 部署）
   - → **对策**：**链和合约地址一律以项目方书面确认为准，不用表格填的**

4. **"活期"标签不可信**
   6 个协议标活期但实际有队列/季度窗口 —— 见 [组合层风险与交叉依赖.md](组合层风险与交叉依赖.md) 第四节
   - → **对策**：调研时**赎回条款必须去 docs 的 FAQ 页确认**，不看营销页

5. **同一产品多个收益率口径**
   USD.AI 出现 8% / 10–15% / 13–17% / 20% 四个数字；Theo 出现 5% / 5.40% / 8.27% / 5–12%
   - → **对策**：区分"目标收益 / 历史平均 / 当前 7 日年化 / 含积分激励"，**前端一律用自算的 7d 或 30d 实测值**

6. **搜索引擎对小众 ticker 无效**
   `QYLDon`、`JAAAon`、`PPLUS`、`nFXCF` 直接搜基本搜不到 —— 要搜**底层资产名**（"Global X Nasdaq 100 Covered Call ETF tokenized"）或**平台机制**（"Ondo Global Markets dividend reinvest"）

## 四、还缺什么（下一轮补充调研的清单）

| 缺口 | 影响 | 获取途径 |
|------|------|---------|
| **合约地址（几乎全部协议）** | 无法开始解析 | 项目方书面提供 / DD 文档 / 浏览器打开产品页看 |
| **DD 文档内容** | 本次完全没读 DD（不在 git 仓库里，只有文件名） | 找 Cece / Terry 要，或在 Confluence / 共享盘找 |
| **赎回条款细节** | 决定"赎回中"状态设计 | 项目方 |
| **NAV 更新频率** | 决定天级曲线是否成立 | 项目方（Midas / DigiFT / Asseto 尤其关键） |
| **投资者准入门槛** | 决定产品能否上线（OnRe / DigiFT / XAUE 是红线） | 项目方 + 法务 |
| **历史 NAV 数据** | PRD 待确认事项#1（NAV 回溯） | 项目方 or archive node 自己跑 |

## 五、本次使用的工具

- 检索：WebSearch（英文 query 效果远好于中文）
- 抓取：WebFetch（对 docs 站有效，对 SPA / Cloudflare 站无效）
- 内网仓库：`git clone --depth=1 https://git.toolsfdg.net/scott-l/DEFI---RWA---.git`（内网不能用 WebFetch）
